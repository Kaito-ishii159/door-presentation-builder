# DoorBoard Studio — prototype

建具メーカー向け「見積書PDF → お施主様向けプレゼンボード」のブラウザ試作品です。

## GitHub Pages

公開URL: https://kaito-ishii159.github.io/door-presentation-builder/

このプロジェクトはビルド不要の静的サイトです。デプロイ設定は `.github/workflows/pages.yml` にあり、`main` へのpushまたは手動実行で構文検証・アップロード・公開を行います。

### 初回設定と `Configure Pages` の404からの復旧

1. リポジトリ管理者が `Settings → Pages → Build and deployment → Source` で **GitHub Actions** を選択し、Pagesを有効化します。
2. Actionsの `Deploy prototype to GitHub Pages` から `Run workflow` を実行します。既存の失敗実行では `Re-run failed jobs` でも再実行できます。
3. `Configure Pages`・`Upload site artifact`・`Deploy` が成功し、公開URLが表示されることを確認します。

`Get Pages site failed ... Not Found` はPagesの初期設定を確認してください。`actions/configure-pages` の `enablement: true` を追加するだけでは、標準の `GITHUB_TOKEN` で初回サイト作成はできません。[公式Actionの権限要件](https://github.com/actions/configure-pages/blob/v5/action.yml)に従い、初期設定は管理画面または既存の適切な管理権限で行います。新しいトークンやシークレットをコードに保存する必要はありません。

## できること

- 固定帳票の列・行座標で見積書PDFを抽出（列順・境界・表範囲を調整可能）
- PDF.jsの画像化＋Tesseract.jsの列別日本語OCRを手動実行（全ページ、最大200。明示した上限による部分検証にも対応）
- WDごとの複数行・ページをまたぐ明細を保持し、競合・低信頼度・未認識項目を「要確認」と表示
- 原文・ページ・候補を確認して修正し、抽出時点／手修正後のJSONを保存
- 正解JSONと比較して5項目の完全一致率・不一致一覧を表示（実帳票は未測定）
- 建具番号・設置場所・品番・寸法・色の編集、アイテムの追加・削除
- 商品画像の手動登録（ブラウザ内のみ）
- 間取り図PDF／画像の読み込み、クリックによる番号配置とドラッグによる移動
- PDFの部屋名テキスト座標から、部屋名付近への**仮配置**（開口部への正確な自動配置ではない）
- A4横の印刷レイアウトをブラウザの印刷画面から「PDFとして保存」
- 編集状態のJSONエクスポート／インポート

詳しい設定・精度の定義・架空サンプルの測定結果は [OCR検証手順と制限](docs/ocr-validation.md) を参照してください。

## 技術構成

- HTML / CSS / JavaScript (静的サイト)
- Mozilla PDF.js (CDN、PDF読み込み。日本語CIDフォント用CMap・標準フォントも同じバージョンのCDNから取得)
- Tesseract.js (CDN、OCRはユーザー操作時だけ実行)
- サーバー、DB、OpenAI API、APIキーは不要
- GitHub Pages と GitHub Actions

Reactへの移行は本番要件が固まってからでも可能です。初期検証ではシンプルな構成を優先しています。

## 重要な制約

1. 本リポジトリは公開リポジトリです。**顧客の見積書・間取り図・商品画像・実名情報をコミットしないでください。** 同梱図面と品番は架空のものです。
2. アップロードした資料の中身は、アプリによってサーバーに送られません。ただしPDF/OCRのJavaScriptライブラリはCDNから読み込みます。機密運用時にはライブラリのセルフホストやアクセス制御を検討してください。
3. PDFの構造・文字配置によっては、抽出結果が不完全になります。OCRは誤認識するため、メーカー側の最終確認が必須です。
4. 「部屋名から仮配置」は部屋名テキストの場所へ番号を仮置きするだけで、建具の実際の開口部を推定・保証しません。位置は手動で調整してください。
5. 商品画像の型番自動対応表・AIによる図面解析・ログイン・クラウド保存は未実装です。
6. GitHub Pagesは商用SaaSのホスティング用途には適しません。本プロジェクトのPages利用は技術検証・試作の範囲を想定します。

## 使い方

1. サイトを開き、架空デモを確認します。
2. 「見積書の読取・精度検証」で列順・境界・表範囲を合わせ、見積書PDFを選択します。画像PDFは「画像PDFをOCRで読み取る」を実行します。
3. 誤認識箇所を編集し、メーカーから提供された商品画像を各行に登録します。
4. 間取り図PDF／画像を読み込み、番号を選択して図面をクリック／ドラッグします。
5. 「PDFに保存」→ ブラウザの「PDFとして保存」を選択します。
6. 正解JSONを読み込むと項目別完全一致率を表示します。原本のWD初出順で比較するため、正解の並び順を合わせてください。
7. 読取結果・精度結果・編集状態はそれぞれJSONで保存できます。抽出文字も機密情報として扱い、公開リポジトリへ追加しないでください。

## 開発時の検証

```bash
node --check assets/app.js
node --test tests/*.test.mjs
```

PRでは構文・抽出ロジックの回帰テストを実行し、`main` へのpushでテスト成功後にPagesへ公開します。実際のPDF画像化・OCRと印刷はブラウザでも検証してください。
